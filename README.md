# open-collections-maintainer

Keeps up-to-date Postman collections for projects that don't publish their own.

The published surface is the **Open Collections** Postman team, fronted by
<https://opencollections.tech/> — 16 workspaces and 30 collections covering infrastructure,
social, entertainment, auth, AI, productivity, and utility APIs. Upstream sources are watched
on a weekly cadence and the collections updated to match.

## Layout

```
open-collections-maintainer/
├── AGENTS.md                  # Agent contract — scope, workflows, conventions (start here)
├── CLAUDE.md                  # Claude Code specifics only
├── postman/collections/
│   ├── INVENTORY.md           # Full registry: every collection, source, ID, status
│   ├── dapr.md                # Dapr — docs-diff workflow
│   └── kubernetes.md          # Kubernetes — one collection per GA version
└── astro/                     # Astropods agent scaffold (separate concern — see astro/README.md)
```

## Where to start

[`postman/collections/INVENTORY.md`](postman/collections/INVENTORY.md) is the source of truth:
for each collection it records the workspace and collection IDs, the linked Postman spec, the
exact upstream path or URL, auth setup, and current sync status.

[`AGENTS.md`](AGENTS.md) is the working contract — how to determine scope, the per-source-type
sync workflows, and the Postman MCP limitations worth knowing before you start writing.

## Sync workflow

Collections fall into four groups by how their source is tracked:

| Kind | Examples | How it syncs |
| --- | --- | --- |
| Spec-backed | Kubernetes, Radarr, Firecrawl, ACP, Agentic Commerce, Spotify | update the Postman spec file, then sync the collection |
| Docs-backed | Dapr | diff upstream markdown between versions, hand-patch requests |
| Discovery-backed | Google Keep | compare the discovery doc revision and method list |
| Manual | Social Media Flow (×6), Geekbot, QR Code Generator, Classter | reviewed by hand — no machine-readable source |

Tooling: the Postman MCP server (`mcp.postman.com`) for all Postman work, `gh` CLI for GitHub.
Never the Postman CLI or direct `api.postman.com` calls.

## The `astro/` directory

An Astropods/Mastra agent scaffold, generated by `ast init`. It is **not** part of the collection
maintenance work and is currently a stub — a chat agent on `ollama/llama3.1:8b` with no tools
wired up. See [`astro/README.md`](astro/README.md).
